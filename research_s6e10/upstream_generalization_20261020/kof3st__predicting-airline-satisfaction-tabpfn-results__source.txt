# 1. Problem Statement

## 1.1. Competition Overview

The **Playground Series - Season 6, Episode 10** is part of Kaggle's monthly series of machine learning competitions designed to help participants practice and improve their data science skills.

The objective of this competition is to predict airline passenger satisfaction based on passenger characteristics, travel information, flight service ratings, and flight delays.

The dataset is synthetic: it was generated by a model trained on a real-world airline passenger satisfaction survey. Feature distributions are close to the original data, but they may contain artifacts that are not present in real observations.

The competition provides three files:

- **`train.csv`** - contains passenger features and the target variable `satisfaction`;
- **`test.csv`** - contains passenger features without the target variable. Predictions for this dataset must be submitted to Kaggle;
- **`sample_submission.csv`** - provides an example of the required submission format.

The target variable `satisfaction` is stored as a boolean value:

- `False` - the passenger is neutral or dissatisfied;
- `True` - the passenger is satisfied.

The submission file must contain two columns: `id` and `satisfaction`, where `satisfaction` is the **predicted probability** that the passenger is satisfied.

The competition uses the **Area Under the Receiver Operating Characteristic Curve (ROC-AUC)** as its evaluation metric. ROC-AUC measures how well a model distinguishes between positive and negative examples by comparing their predicted scores across all possible classification thresholds. The metric depends only on the ordering of the predictions, so the choice of a decision threshold does not affect the score.

## 1.2. Machine Learning Problem

From a machine learning perspective, this is a **binary classification problem with probabilistic predictions**.

For each passenger, a set of characteristics is available:

$$
X = (x_1, x_2, \ldots, x_n)
$$

The objective is to estimate the probability that the passenger is satisfied:

$$
\hat{p} = P(y = 1 \mid X)
$$

where:

- $X$ represents the available passenger features;
- $y = 0$ represents a neutral or dissatisfied passenger;
- $y = 1$ represents a satisfied passenger;
- $\hat{p}$ is the predicted probability of satisfaction, ranging from 0 to 1.

A probability close to 0 indicates that the model considers passenger dissatisfaction more likely, while a probability close to 1 indicates that satisfaction is more likely.

Although the target variable contains only two classes, the model's predicted probabilities provide more information than hard class labels. For example, predictions of 0.52 and 0.97 both correspond to the positive class when using a threshold of 0.5, but they express different levels of confidence.

Since ROC-AUC evaluates only the ranking of the predicted probabilities, the models are compared by their ability to assign higher probabilities to satisfied passengers than to neutral or dissatisfied ones, rather than by the accuracy of hard class labels.

The `train.csv` dataset will be used to discover patterns and train the models, while `test.csv` will be used only for generating the final predictions for Kaggle.

# 5. Exploratory Data Analysis

The goal of the EDA is to understand how each feature relates to satisfaction and what that means for preprocessing and modelling.

Two helpers are used throughout: `satisfaction_table` returns the number of passengers, their share, and the satisfaction rate for each value of a feature, and `plot_satisfaction_by` shows the same as two bar charts. The dashed line on the plots is the overall satisfaction rate.

OVERALL_RATE = train[TARGET].mean()


def satisfaction_table(data, col, order=None):
    """Returns the number of passengers, their share, and the satisfaction rate for each value of a feature."""
    table = data.groupby(col)[TARGET].agg(["count", "mean"])
    table = table.rename(columns={"count": "Passengers", "mean": "Satisfaction rate"})
    table["Share"] = table["Passengers"] / len(data)

    if order is not None:
        table = table.reindex(order)

    return table[["Passengers", "Share", "Satisfaction rate"]]


def plot_satisfaction_by(data, col, order=None):
    """Draws the number of passengers and the satisfaction rate for each value of a feature."""
    table = satisfaction_table(data, col, order).reset_index()
    table[col] = table[col].astype(str)

    _, axes = plt.subplots(1, 2, figsize=(14, 5))

    sns.barplot(data=table, x=col, y="Passengers", color="tab:blue", ax=axes[0])
    axes[0].set_title(f"Passenger Distribution by {col}")
    axes[0].set_xlabel(col)
    axes[0].set_ylabel("Number of passengers")

    sns.barplot(data=table, x=col, y="Satisfaction rate", color="tab:green", ax=axes[1])
    axes[1].axhline(OVERALL_RATE, color="black", linestyle="--", linewidth=1)
    axes[1].set_title(f"Satisfaction Rate by {col}")
    axes[1].set_xlabel(col)
    axes[1].set_ylabel("Satisfaction rate")
    axes[1].set_ylim(0, 1)

    plt.tight_layout()
    plt.show()

### Individual Predictive Power

To rank the ratings, each one is used as the only predictor and scored with ROC-AUC in two ways:

- **raw values** - the rating itself; this only captures "the higher, the better";
- **value means** - each rating value is replaced with its satisfaction rate from the heatmap; this captures any shape and shows the best a single rating can do.

With at most six values and thousands of passengers behind each of them, the value means do not overfit.

rating_auc = pd.DataFrame({
    "Raw values": {
        col: roc_auc_score(train[TARGET], train[col])
        for col in RATING_COLS
    },
    "Value means": {
        col: roc_auc_score(train[TARGET], train[col].map(rating_satisfaction.loc[col]))
        for col in RATING_COLS
    },
})

rating_auc = rating_auc.sort_values("Value means", ascending=False)

## EDA Conclusions

- The strongest signals come from `Type of Travel`, `Class`, and `Online boarding`. `Gender`, the delays, and a couple of ratings are weak on their own.
- Most relationships are non-linear, with thresholds in the ratings (4-5 vs. 1-3), age (39 and 61), flight distance (1,200-1,800), and arrival delay (over 5 minutes).
- Many effects exist only for business travellers, so the features interact strongly.
- Zero ratings are not low ratings, at least for the online services.
- `Arrival Delay in Minutes` has a few missing values that can be filled from the departure delay.
- Several sharp edges in the distributions are probably artifacts of the synthetic data.

### Comparison of Imputation Strategies

Each strategy is tested on the rows where the arrival delay is known, as if it were missing:

- **zero** - assume there was no delay, the most common case;
- **median** and **mean** of the known arrival delays;
- **departure delay** - take the departure delay of the same flight.

Besides the usual error (MAE) and the share of exact matches, the last column checks whether the strategy gets the delay over 5 minutes right. That is the threshold where satisfaction drops.

known = train.loc[train["Arrival Delay in Minutes"].notna()]
actual = known["Arrival Delay in Minutes"]

median_value = actual.median()
mean_value = actual.mean()

strategies = {
    "Zero": pd.Series(0.0, index=known.index),
    f"Median ({median_value:.0f})": pd.Series(median_value, index=known.index),
    f"Mean ({mean_value:.2f})": pd.Series(mean_value, index=known.index),
    "Departure delay": known["Departure Delay in Minutes"].astype(float),
}

imputation_comparison = pd.DataFrame({
    name: {
        "MAE": (predicted - actual).abs().mean(),
        "Exact match": (predicted == actual).mean(),
        "Same significant delay status": ((predicted > 5) == (actual > 5)).mean(),
    }
    for name, predicted in strategies.items()
}).T

display(imputation_comparison)

Zero and median are the same strategy here, since the median delay is 0. They often hit the exact value, simply because most flights are on time, but they never predict a delay. The mean is useless: 1.13 minutes never matches a real delay.

The departure delay gives the smallest error and best catches significant delays, so it is used for imputation. It should work even better on the missing rows, where delayed departures are three times more common.

The imputation uses only the values of the same row, with no statistics computed over the dataset, so it cannot leak information between cross-validation folds. It is therefore applied directly to both datasets at the start of Section 7.

# 7. Feature Engineering

New features are built from the EDA findings. Each one is computed from the other values in the same row, without any dataset statistics or the target, so they can be added to train and test before cross-validation with no risk of leakage.

The thresholds for age and flight distance groups come from the EDA.

The helper `feature_auc` evaluates each feature with the same two ROC-AUC variants as in the EDA (raw values for numerical features only) and also reports the number of missing values.

def feature_auc(data, cols):
    """Returns the number of missing values and the single-feature ROC-AUC of each feature."""
    rows = {}

    for col in cols:
        mask = data[col].notna()
        y = data.loc[mask, TARGET]

        value_means = data.loc[mask].groupby(col, observed=True)[TARGET].transform("mean")

        if pd.api.types.is_numeric_dtype(data[col]):
            raw_auc = roc_auc_score(y, data.loc[mask, col])
        else:
            raw_auc = np.nan

        rows[col] = {
            "Missing": int((~mask).sum()),
            "Raw values": raw_auc,
            "Value means": roc_auc_score(y, value_means),
        }

    return pd.DataFrame.from_dict(rows, orient="index")

# 10. Baseline

Before training any models, a simple reference point is needed: a model is only useful if it beats it.

## 10.1. Evaluation Helpers

Three helpers are reused for every model:

- `predict_proba_in_chunks` - predicts the probability of satisfaction for 20,000 passengers at a time. Some models need a lot of memory per predicted row and can't predict all 140,000 passengers of a validation fold at once; for the others it makes no difference;
- `cross_validate_model` - trains a fresh copy of the model on each fold, predicts the validation part, and returns the ROC-AUC and training time for every fold, together with the out-of-fold predictions;
- `summarize_folds` - returns the mean and the standard deviation of ROC-AUC over the folds, the ROC-AUC of all out-of-fold predictions together, and the total training time.

def predict_proba_in_chunks(model, X, chunk_size=20_000):
    """Returns the predicted probability of the positive class, computed chunk by chunk."""
    return np.concatenate([
        model.predict_proba(X.iloc[start:start + chunk_size])[:, 1]
        for start in range(0, len(X), chunk_size)
    ])


def cross_validate_model(model, X, y, cv):
    """Returns the ROC-AUC and training time of every fold and the out-of-fold predictions."""
    oof = np.zeros(len(y))
    rows = []

    for train_idx, valid_idx in cv.split(X, y):
        start = time.time()

        fold_model = clone(model).fit(X.iloc[train_idx], y.iloc[train_idx])
        oof[valid_idx] = predict_proba_in_chunks(fold_model, X.iloc[valid_idx])

        rows.append({
            "ROC-AUC": roc_auc_score(y.iloc[valid_idx], oof[valid_idx]),
            "Time (s)": time.time() - start,
        })

    fold_scores = pd.DataFrame(rows, index=pd.RangeIndex(len(rows), name="Fold"))

    return fold_scores, oof


def summarize_folds(fold_scores, oof, y):
    """Returns the mean and spread of ROC-AUC over the folds, the overall out-of-fold ROC-AUC, and the total time."""
    return {
        "CV ROC-AUC": fold_scores["ROC-AUC"].mean(),
        "Std": fold_scores["ROC-AUC"].std(),
        "OOF ROC-AUC": roc_auc_score(y, oof),
        "Time (s)": fold_scores["Time (s)"].sum(),
    }

# 12. TabPFN-3.5

TabPFN is a tabular foundation model: a transformer pre-trained on millions of synthetic datasets. It doesn't learn any weights on our data. `fit` only stores the training rows, and at prediction time the model reads them as context, together with the rows to predict, in a single forward pass.

The memory needed grows with the size of the context, so the 700,000 labelled passengers can't be used all at once. Instead, TabPFN is an ensemble of several forward passes, and each of them gets its own random subsample of the training rows. Together, the subsamples cover the whole training set.

Every prediction is expensive: the whole context is processed again for every chunk of predicted rows. Full cross-validation would mean predicting 700,000 passengers, more than twice the size of the test set, which doesn't fit into the 12 hours of a Kaggle session. Instead, the model is checked on a hold-out sample from the first fold, where it can be compared with LightGBM on exactly the same passengers.

TabPFN needs a GPU. Its weights are free for non-commercial use after accepting the Prior Labs licence; the access token is read from the `TABPFN_TOKEN` environment variable.

## 12.1. Model Setup

The model runs on the two T4 GPUs of a Kaggle session (16 GB each); the passes of the ensemble are split between them.

The settings:

- `n_estimators=10` - the number of forward passes in the ensemble;
- `SUBSAMPLE_SAMPLES=250_000` - the context size of every pass. This is the main lever of the model's quality, and 250,000 rows are about the most that fits into the memory and time budget. With `"balanced"` sampling, the passes take turns drawing from one shuffled queue of rows, so every passenger gets into the context of three or four passes;
- `memory_saving_mode` and `inference_precision="autocast"` - the computations are split into smaller parts and run in half precision, which keeps a large context within the GPU memory.

TabPFN gets only the original features, without the preprocessor. It encodes the text columns itself and treats them as categories, and the engineered features barely helped even LightGBM. Every extra column adds to the time and memory of every pass, so they are better spent on a larger context.

DEVICE = ["cuda:0", "cuda:1"] if torch.cuda.device_count() > 1 else "cuda"

print(f"Device: {DEVICE}")

tabpfn = TabPFNClassifier.create_default_for_version(
    ModelVersion.V3_5,
    device=DEVICE,
    n_estimators=10,
    inference_config={
        "SUBSAMPLE_SAMPLES": 250_000,
        "SAMPLE_SUBSAMPLING_METHOD": "balanced",
    },
    memory_saving_mode=True,
    inference_precision="autocast",
    random_state=RANDOM_STATE,
    show_progress_bar=True,
)

## 12.2. Hold-Out Check

The model is fitted on the training part of the first fold and predicts 10,000 passengers of its validation part. LightGBM's out-of-fold predictions for these passengers come from the model trained on the same fold, so the comparison is fair. The rank average of the two models is checked as well.

The predicted rows are processed in chunks of 50,000: the larger the chunk, the fewer times the context is processed again. Here all 10,000 passengers fit into one chunk, so the time of this cell is roughly the time of one chunk, and it gives a lower bound for predicting the test set.

TABPFN_CHUNK_SIZE = 50_000

train_idx, valid_idx = next(skf.split(X, y))
check_idx = valid_idx[:10_000]

start = time.time()

tabpfn_check = clone(tabpfn).fit(X[FEATURES].iloc[train_idx], y.iloc[train_idx])
tabpfn_check_pred = predict_proba_in_chunks(tabpfn_check, X[FEATURES].iloc[check_idx], TABPFN_CHUNK_SIZE)

check_time = time.time() - start
n_test_chunks = int(np.ceil(len(X_test) / TABPFN_CHUNK_SIZE))

print(f"Time for {len(check_idx):,} passengers: {check_time / 60:.0f} min")
print(f"Estimated time for the test set: at least {check_time * n_test_chunks / 3600:.1f} h")

check_predictions = pd.DataFrame({
    "LightGBM": lgbm_oof[check_idx],
    "TabPFN-3.5": tabpfn_check_pred,
})

check_predictions["Rank average"] = check_predictions.rank(pct=True).mean(axis=1)

holdout_scores = check_predictions.apply(lambda pred: roc_auc_score(y.iloc[check_idx], pred))

display(holdout_scores.to_frame("Hold-out ROC-AUC"))

The model is fitted on all labelled passengers and predicts the test set. The predictions are saved to a file right away, so that they can be reused for blending without repeating the hours of computation.

The fitted model is saved with TabPFN's own function. The file contains the settings and the fitted state, including the training data that serves as context, but not the foundation model weights, which are downloaded again when the model is loaded with `load_fitted_tabpfn_model`.
