# S6E10 | Stacking every public OOF library | nested CV 0.96205 · LB 0.96167

Many people in this episode have shared out-of-fold (OOF) predictions on the same split,
`StratifiedKFold(5, shuffle=True, random_state=42)` over `train.csv`. Each public stack I found combines only some of them.
This notebook puts **all of them** into one logistic-regression stack and measures, with a **nested** CV, what every
library adds.

| stack | members | nested CV |
|---|---:|---:|
| goodpjw2008 Part 8 (48 members, their own nested CV) | 48 | 0.961933 |
| najiama blend 02 (OOF of the best public submission) | 1 | 0.961920 |
| public libraries **without** goodpjw's 40 own models | 79 | 0.962003 |
| all public libraries | 119 | 0.962004 |
| **+ the 5 models of busyaprime (this notebook, v3)** | **124** | **0.96205** |

**Public LB 0.96167** for the 124-member stack (the 119-member version of this notebook scored 0.96163). The 79-member
variant scored 0.96155, a gap I can't distinguish from noise; more on that below.

**What moved the stack** (sections 4 and 4b):
- the **TabPFN-3.5 / TabICL** foundation members: **+0.00012**, positive in all 5 outer folds (+0.00006 to +0.00023);
- the **10-fold members** of sachith7: +0.0001 in a stack without goodpjw2008's 40 own models, but only **+0.000035**
  in the full stack (they overlap with those models); still positive in every fold;
- busyaprime's RealMLP (Vladimir Demidov's configuration), worth about +0.00003 on top of everything else;
- the rest, all GBDT / RealMLP members on similar features, adds only +0.00001 to +0.00003 each.

**A note on the public LB.** The public part is a small share of the test set. On OOF subsamples of that size, the SD of the
difference between two *different* strong stacks is about 1e-4. So 0.96160 vs 0.96165 is noise, and I select by nested CV
only (no weights tuned on the LB, no rounding or extrapolation tricks).

Nothing here is trained from scratch. All the credit for the members goes to their authors (section 1); please upvote their work.

import glob, os, time
import numpy as np, pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import StratifiedKFold

T0 = time.time()
def find_dir(slug):
    # works with both Kaggle input layouts: /kaggle/input/<slug> and /kaggle/input/{datasets,notebooks,competitions}/<owner>/<slug>
    hits = [p for p in glob.glob(f'/kaggle/input/**/{slug}', recursive=True) if os.path.isdir(p)]
    assert hits, f'input not attached: {slug}'
    return sorted(hits, key=len)[0]

COMP = find_dir('playground-series-s6e10')
tr = pd.read_csv(f'{COMP}/train.csv', usecols=['id', 'satisfaction'])
te = pd.read_csv(f'{COMP}/test.csv', usecols=['id'])
y = tr['satisfaction'].astype(int).values
NTR = len(y)
OOF, TEST, SRC = {}, {}, {}

def add(name, o, t, src):
    o, t = np.asarray(o, float), np.asarray(t, float)
    assert o.shape == (NTR,) and t.shape == (len(te),), (name, o.shape, t.shape)
    assert np.isfinite(o).all() and np.isfinite(t).all(), name
    OOF[name], TEST[name], SRC[name] = o, t, src

def by_id(df, ids, col):
    return df.set_index('id')[col].loc[ids].values

## 3. Nested logistic-regression stack on logits

The stacker is `LogisticRegression(C=1)` on clipped logits of all members. To score it honestly, it is itself
cross-validated (meta folds `StratifiedKFold(5, shuffle=True, random_state=7)`, as in goodpjw's Part 8): each row's stack
prediction comes from a stacker that never saw that row. The submission uses one stacker fitted on all OOF rows.

def logit(p):
    p = np.clip(p, 1e-6, 1 - 1e-6)
    return np.log(p / (1 - p))

Z = np.column_stack([logit(OOF[n]) for n in names])
ZT = np.column_stack([logit(TEST[n]) for n in names])
idx = {n: i for i, n in enumerate(names)}
import gc
del OOF, TEST   # from here on only the logit matrices are used (keeps the run well inside the RAM limit)
gc.collect()
META = list(StratifiedKFold(5, shuffle=True, random_state=7).split(Z, y))

def nested(cols, C=1.0):
    ci = [idx[c] for c in cols]
    out = np.zeros(NTR)
    for a, b in META:
        out[b] = LogisticRegression(C=C, max_iter=3000).fit(Z[a][:, ci], y[a]).decision_function(Z[b][:, ci])
    return out

t = time.time()
stack_oof = nested(names)
print(f'nested CV, all {len(names)} members: {roc_auc_score(y, stack_oof):.6f}  '
      f'folds: {" ".join(f"{roc_auc_score(y[b], stack_oof[b]):.5f}" for _, b in META)}  ({time.time() - t:.0f}s)')

## 4. What each source is worth (leave one source out)

full_auc = roc_auc_score(y, stack_oof)
rows = []
for s in pd.Series(SRC).unique():
    cols = [n for n in names if SRC[n] != s]
    rows.append((s, sum(SRC[n] == s for n in names), roc_auc_score(y, nested(cols)) - full_auc))
abl = pd.DataFrame(rows, columns=['left out', 'members', 'Δ nested CV']).sort_values('Δ nested CV')
abl['Δ nested CV'] = abl['Δ nested CV'].map(lambda v: f'{v:+.6f}')
abl

## 4b. Are the gains consistent across folds?

A question from the discussion: are the gains of the foundation members and the 10-fold members spread over the outer
folds, or concentrated in one? Each group is dropped from the full stack, and the per-fold AUC difference is shown.

FM = [n for n in names if 'tabpfn' in n or 'tabicl' in n]
K10 = [n for n in names if SRC[n] == 'sachith7' and '_k10' in n]
def per_fold(cols):
    s = nested(cols)
    return [roc_auc_score(y[b], s[b]) for _, b in META] + [roc_auc_score(y, s)]
full_f = per_fold(names)
rows = []
for lab, drop in [(f'{len(FM)} TabPFN / TabICL members', FM), (f'{len(K10)} ten-fold members', K10), ('both', FM + K10)]:
    rest = per_fold([n for n in names if n not in drop])
    rows.append([lab] + [f'{a - b:+.6f}' for a, b in zip(full_f, rest)])
pd.DataFrame(rows, columns=['gain of'] + [f'fold {i}' for i in range(5)] + ['pooled'])

## Takeaways

- Stacking everything that is already public beats every single public stack on nested CV (0.96205 vs 0.96193),
  without training a model.
- New *diverse* members matter more than tuning: the foundation models carry most of the gain, in every fold.
- A negative result: I added four more 10-fold members of my own on the same features (XGBoost with route features, an
  original-data teacher and aux expected values; RealMLP; two TabM). Each scored 0.9600–0.9611 alone, but the stack went
  from 0.962013 to 0.962002. GBDT and NN members on these features are saturated.
- Choose by nested CV, not by public LB: differences below ~1e-4 on the public LB are noise.
